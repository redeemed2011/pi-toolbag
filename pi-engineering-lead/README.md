# pi-engineering-lead

Engineering Lead (Sam's Grok Bot on bb-file) and the pi agent talk through [`dev-agent-bridge`](../dev-agent-bridge/README.md). This extension is a thin shim over that program.

- **Arriving messages.** An interactive session polls `dev-agent-bridge` every 3 seconds (`PI_ENGINEERING_LEAD_POLL_MS`). While the agent is idle with nothing queued, it takes every new message and hands them to `pi.sendMessage` as one message that starts a turn. While a model call or a tool runs, it only renews its lease (`take --hold`), so a message waits in the inbox, not in pi's memory, and does not interrupt that call. At the next completed turn, `turn_end` takes the waiting messages and writes them into the session at that boundary, before the next model call. That includes a turn whose tool calls returned in the middle of a long run, so the agent sees a message within seconds of its current tool finishing, not only when the whole run ends. Mid-run, the message ends with a line telling the agent to carry on with its work. A finished turn continues on the message. An aborted or errored turn takes nothing. The wait is as long as the tool that is running: a 20-minute test run holds a message for up to 20 minutes. Taken ids are recorded by `dev-agent-bridge` (`state/delivered`), so a restart does not deliver them again. The editor is never touched, so Sam's draft stays where it is and is not sent. A reply to an ask this session sent, and a later message on a topic this session last wrote on, come to this session even while another session or Brazos holds the lease: `engineering_lead_send` passes the session id as `DEV_AGENT_BRIDGE_SESSION`. The session holding the lease receives every other message, and also a message for a session that has not polled in 30 seconds. `/engineering-lead listen` moves the rest of the messages to this session.
- **Sending.** `engineering_lead_send` (kind, topic, body, reply_to, ctx, commit, file) runs `dev-agent-bridge send` with the body on stdin.
- `/engineering-lead status` shows the listener and how many messages wait. `/engineering-lead release` gives the lease up.

Needs `~/.cargo/bin/dev-agent-bridge` or `DEV_AGENT_BRIDGE_BIN`. Without it nothing is received, and the tool says it is not installed.

## Test

`npm test` here runs the real program against a temporary inbox. `tests/busy-proof.sh` runs real pi in tmux, drops a message while the first of two bash tools is running, and shows it join right after that tool returned, before the second tool call, with the work carried on to the end. `tests/draft-proof.sh` runs real pi in tmux with one model call: it types a draft, drops a message, and shows the draft still in the editor and absent from the session.
